# Windows 与 macOS 功能对照及合并审查

Mac 版已补上桌面图标、玩法、界面和生命周期处理的主要差距，并继续按 Windows 当前源码还原外观。当前证据来自本机 Apple Silicon 测试、生成数据测试及源码检查。Intel、macOS 13、真实多屏切换和线上排名仍有待验证，因此暂时不能宣称两个平台已经具有相同的成熟度。

对照基准为上游 Windows v0.2.4 的提交 [`5d1bb4ce1d18b6791d16ae98ce0d1ad6a663252d`](https://github.com/liuxiaogang-com/desktop-icon-billiards/commit/5d1bb4ce1d18b6791d16ae98ce0d1ad6a663252d)。已发布功能以该提交的 [README](https://github.com/liuxiaogang-com/desktop-icon-billiards/blob/5d1bb4ce1d18b6791d16ae98ce0d1ad6a663252d/README.md) 和实现为准；尚未合并的 PR 不计入发布基准。成绩卡按当前 `dib/card.py` 的四列统计布局实现，仓库内较早的示例截图采用不同排版。

## 原作者提出的要求

[Mac issue #9 的回复](https://github.com/liuxiaogang-com/desktop-icon-billiards/issues/9#issuecomment-6853106839)表示：作者尝试过 Mac 支持，但支持情况不够好，需要更多时间测试。该回复没有列出完整的 Mac 验收标准，也没有承诺合并移植版本。

[语言切换 PR #12 的审查](https://github.com/liuxiaogang-com/desktop-icon-billiards/pull/12#pullrequestreview-5920304505)明确要求：

- 先更新开关状态等最终文字，再测量并排布工具条。语言改变导致尺寸变化后，要重新限制位置，使工具条留在当前显示器的工作区，避免无故移到另一块屏幕。
- 在右边缘、底边缘、较窄工作区和高 DPI 条件下，双向切换语言，确认所有控件和完整作者署名都能访问。
- 同步刷新已打开的成绩、排行榜、白球外观、赞赏和更新窗口，并保留用户状态。远端提供的更新说明不要求自动翻译。
- 立即更新与语言有关的画面缓存和字体，由拥有绘制窗口的线程执行渲染变更。
- 补充工具条边界和刷新回归测试，并检查两种语言下的 Windows 打包程序。切换语言不能重开球局、重置计时或排名、丢弃已选图片，也不能依赖悬停才刷新文字。

这些要求针对尚未合并的 Windows 国际化 PR。Mac 版采用其中的边界和状态保留标准进行检查；这不代表 PR #12 已合并，也不代表原版 Windows 程序已经完成英文实机验证。Mac 界面默认简体中文，英文可从语言菜单切换。

[局域网 PR #7 的回复](https://github.com/liuxiaogang-com/desktop-icon-billiards/pull/7#issuecomment-6858043124)说明：作者希望保留轻量、随开随玩的桌面体验，尚未确定双人轮流击球、计分与胜负规则。审查还提出网络数值校验、摆球回合权限、双方确认重开、画面平滑，以及办公网络防火墙和设备隔离问题。因此，局域网对战仍未合并，不属于此次已发布功能对照的范围。

先前打包版本已在这台 Apple Silicon Mac 上实际操作，记录过简体中文与英文双向切换后仍保留 12 杆、4 颗入袋的球局状态。该记录验证的是当时的打包版本。本轮已检查最终 GameView 的离屏画面和生成的成绩卡。通用包已构建，`lipo -archs` 确认为 `arm64 x86_64`，`codesign --verify --deep --strict` 通过；ZIP 约 2.3 MB。可见 UI 工具目前无法取得旧进程窗口（`cgWindowNotFound`），因此尚未重启该进程或宣称最终包的完整键鼠流程已验收。

原 Windows 测试在 Mac 上使用 Python 3.12 与锁定的 Pillow 13.0.0 执行过以下模块：

```sh
uv run --no-project --python 3.12 --with Pillow==13.0.0 python -m unittest \
  tests.test_table tests.test_balls tests.test_card tests.test_rank tests.test_update -v
```

这次发现 99 个测试，其中 94 个通过，5 个会导入 Mac 无法提供的 Windows 图层或排行榜模块。排除这 5 个平台专属方法后，原测试中的其余 94 个全部通过；此次本机运行没有改动这些测试或 Windows 实现。后续 Windows CI 发现的工具条测试修正见下方。被排除的方法为：

- `tests.test_table.BilliardsMotionTests.test_pointer_charges_linearly_in_one_and_a_half_seconds`
- `tests.test_table.BilliardsMotionTests.test_pointer_cycles_and_releases_at_the_current_power`
- `tests.test_table.BilliardsMotionTests.test_release_outside_table_cancels_cycle_and_new_press_starts_at_zero`

完整 Windows 测试与构建仍由新工作流执行：安装原 `requirements-build.txt`，运行 `.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -t . -v`，再调用未改动的 `pwsh -File build.ps1 -SkipDeps` 并保留 EXE 附件。本机的 94 项可移植测试不能替代 Windows 完整测试、打包结果或实际桌面操作。

## CI 状态

[先前的 Mac CI 记录](https://github.com/clark970417-eng/desktop-icon-billiards/actions/runs/44350805476)未获得托管运行器，注释为 `The job was not acquired by Runner of type hosted even after multiple attempts`，步骤列表为空。这发生在 Mac ARM 托管运行器分配阶段，尚未执行编译或测试，不能据此判断为应用构建失败，也不能视为构建成功。

[首次完整 Windows CI](https://github.com/clark970417-eng/desktop-icon-billiards/actions/runs/44367042570)执行 163 项测试，162 项通过，1 项失败。失败停在上游 `tests/test_toolbar.py` 的按钮集合断言：测试漏掉已经存在于原版 `dib/panel.py` 的 `white` 白球外观按钮。同一测试还保留旧版单行布局、作者署名层级和回调顺序假设，均与该上游基准的两行分组工具条不符。

现仅校正这一个原版工具条测试：严格比对全部九个按钮、逐个确认回调、检查功能与操作两行的位置、完整署名、可见性、边界和重叠。没有跳过测试或改动 Windows 实现，测试总数仍为 163。修正已完成静态检查，尚未取得修正后 Windows CI 的运行结果；首次运行也因测试失败而未执行 EXE 构建。后续仍需确认完整测试输出及打包附件。

- 使用最终打包 App 检查原作风格的工具条、壁纸模糊、长球杆、原图标、成绩卡、保存与复制、白球裁切，以及隐藏台面后的恢复入口。

- 完成 Developer ID 签署、公证与另一台 Mac 的下载启动测试后，再评估分发体验是否达到正式发布水平。
